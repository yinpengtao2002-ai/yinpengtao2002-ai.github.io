# Checkmi · 业务逻辑说明

版本：1.90　日期：2026年10月4日

本文是当前规则。旧版累计说明已归档，不再用“后面的修订覆盖前面的修订”解释互相冲突的段落。看板在浏览器本地计算；默认演示数据以2027—2031五个实际年份展示，用于熟悉操作，不能视为实际经营数据；不改变用户上传的年份。

## 1. 工作顺序与保存

1. 上传现成损益表；或先打开含 Mapping 规则的完整项目，再通过“接入数据 → 基础数据生成损益”上传销量、车型/版型、年度和售价，核查预览后应用。
2. 原表填错或需要补录时，用“科目与数据”修改基础表；经营假设用“项目参数”调整。
3. 选择查看范围，核对总览和损益。需要留存假设时“加入情景比较”。
4. 用“下载项目”保存 `.checkmi.json` 文件。下次用“打开项目”继续测算。
5. 对外核查损益结果时，再导出 Excel 报表或完整损益模板。

“保存修改”和“加入情景比较”先写入本次页面会话。刷新、关闭页面仍会清空未下载的工作；有未下载内容时，浏览器在允许的情况下提供离开提示。项目文件保留随项目提供的 Mapping、生成时采用的规则版本和参数、基础数据来源规则、原始值、当前修订、现金流、独立对标、当前参数、Mix、全部已存情景及顶部查看范围。后续有修改，应重新下载文件。浏览器不会自动覆盖旧下载文件，也没有向服务器上传用户数据。

“打开项目”会替换当前工作，需要保留当前工作时先下载。文件完整校验通过后才替换；文件错误时保留当前工作。项目文件上限50 MB。图表分页、展开状态等临时界面设置以及现金流页手动选择的折现率/口径不属于项目文件；打开后可重新选择。项目文件与业务上传 JSON 是两种不同格式，分别从“打开项目”和“接入数据”读取。

## 2. 数据来源与范围

一条经营记录对应“项目 × 国家 × 阀点 × 版型 × 年度”。同名版型如果项目、国家或阀点不同，不能混为一条。汇总列、Average、生命周期合计不能再次作为明细加入。金额、比例和销量采用原始精度计算，显示取舍不改变底层数值。

| 来源 | 输入含义 | 集团分摊的默认规则 | 现金流 |
|---|---|---|---|
| 原完整 BC 工作簿 | 原结构的带符号单车值及来源位置 | 按该版型年度基线“集团分摊÷净收入”随净收入与销量联动 | 读取独立现金流表 |
| 标准底表（Excel/CSV/业务 JSON） | 正数单车成本/抵减与比例，系统转为带符号科目 | 按输入的集团分摊率随净收入与销量联动 | 标准模板不含现金流 |
| 基础计划＋项目 Mapping | 按科目最细优先匹配项目规则，结合各版型销量/售价生成 | 采用规则明确指定的单车或费率；不推断为固定预算 | 不生成现金流 |
| 损益格式 Excel | 带符号单车明细；允许直接录入税费与合计 | 上传单车分摊×上传销量形成固定预算，后续销量/Mix不改该预算 | 不拼入演示现金流 |

集团分摊始终进入费用及 EBIT 一次。特殊调整显式填写集团分摊总额后，所选记录使用填写的固定金额；恢复底表后回到各自来源规则。原完整 BC 的集团分摊原本不在费用合计内，看板补计这笔扣减；损益格式已包含，不能再重复扣减。

普通上传入口首次默认替换基础，后续默认追加对标；对标页入口默认追加。明确替换基础会重置当前参数、Mix与旧基础的情景；独立对标继续保留。多文件先解析核查再统一应用，失败文件不会造成部分替换。页面内基础编辑则保留已存情景，详见第4节。

## 3. 模板、识别与空值

“接入数据”提供“上传损益表”和“基础数据生成损益”。后者要求先打开维护侧已配置 Mapping 的完整项目；没有规则时仍可上传现成损益，不能生成。普通测算用户不上传 Mapping，也无需连接数据库。

基础计划支持 Excel、CSV 或 JSON，可下载基础数据 CSV 模板。每行填写车型、版型、日历年度、销量和含税售价；项目、国家、阀点可选，缺省分别为“当前项目”“中国”“现状”。销量为非负整数台数，售价为正数元/台。可选 BOM 单车成本填支出正数元/台，空白采用规则，明确填0采用0，填写时优先于该记录的 Mapping BOM 及其明细。

当前车型为 Modena、Lemans、Kunlun、Ultra，版型填写该车型下的具体配置。基础计划和 Mapping 规则中的这四个名称忽略大小写及首尾空格，统一为上述写法；已保存历史快照不改名。车型名单不表示已配置费用规则，可生成的车型和年度仍以所打开项目的规则覆盖为准。

Mapping 按科目采用“最细规则优先”，从下面四层逐级覆盖。同一条规则可填写多个科目，单车金额和费率均适用：

| 维护范围 | 适用范围 |
|---|---|
| 不填车型、年份、版型 | 本项目所有车型、版型、年度共用 |
| 只填车型 | 该车型全部版型、年度 |
| 填车型和年份 | 该车型该年度的全部版型 |
| 填车型、版型和年份 | 该版型该年度，优先级最高 |

以虚构费率说明匹配顺序：销交服项目默认4%，Modena为5%，Modena的2027年为6%，该年某版型为7%，则该版型使用7%；没有细层规则的其他记录使用最接近的上层规则。细层只修改销交服时，BOM和研发等仍分别继承它们的上层规则。明确填0表示覆盖为0，不填该科目才是继承。

规则可以在完整项目文件中维护；网页读取规则、显示覆盖及匹配依据，生成测算，不提供Mapping编辑入口。只填年份或只填版型的范围不能使用，需同时写明其所属车型，版型规则还须写明年份。同一范围、同一科目重复配置会报冲突；不同范围逐级覆盖不相加。合并后费用合计与其明细同时给规则，或出现费率循环，也会阻止应用，不能重复计费或自动猜拆分。

年度规则只匹配对应年份，不借用相邻年度；有车型或项目通用规则时，其他年份继续继承。继承后必要科目仍缺失时不能生成，也不会补0。仅提供费用合计时，未拆分明细保持空白。页面用“车型 / 版型”显示生成记录，避免不同车型的同名版型混在一起。

上传后先核对规则版本、适用范围、匹配记录、总销量、净收入、毛利率和 EBIT，再“应用生成的损益”。它会替换当前基础并重置当前参数、Mix和已存情景，独立对标保留；需保留原工作时先下载项目。生成后可在“科目与数据”单条或批量调整，再下载项目保存。项目内保留生成时的规则快照；人工调整不修改维护侧 Mapping，后来在项目文件中修改规则并重新打开，也不会自动改写历史测算；再次接入基础计划并确认预览后，才生成采用新规则的测算。

维护侧可在 Mapping 中定义附加费用明细并明确上级，生成后可编辑并汇入所属成本/费用。当前页面没有独立的“新增科目”按钮。正式规则由维护侧提供，本网页不自带小米车型的实际费用或费率。

旧版标准底表不再提供独立上传方式和模板下载入口；已填写的旧表仍可通过现有上传入口识别，历史项目继续兼容。旧版标准模板在“数据填写”页逐行填入真实数据；“填写示例”页仅供参考。必填字段涵盖身份、年度、销量、售价、各成本费用合计与费率。金额按正数元/台，销量按台，费率用小数或 Excel 百分比，例如0.13或13%。无发生额明确填0。标准表的 BOM 不包含另列赠送配置。兼容旧“车型”及新“版型”表头，同义字段重复时提示错误。

损益模板在真实年度/版型的“单车（元）”列填写：Sales为非负整数台数，MSRP为正数元/台，成本、费用和收入抵减使用负号。收入比、Average、生命周期汇总和分隔列不参与上传取数。成本明细空白保留为“未填写”；确实为零应填0。明细缺失不会阻止使用已有父级合计，也不会补造拆分。

模板保留原 BC 字体、灰色斜体、颜色、边框、缩进、列宽、行高、数值格式和底部参数/填写说明，冻结C6，缩放70%。显示位数不影响数值精度。旧版简表继续兼容。

损益格式按标题含义识别年度、版型和单位，支持增删年度/版型、SOP至SOP+999或2000至2099日历年；同一份数据不能混用两种年度体系。支持带年份的现状表头。名称按实际值保留；完整导出仅受 Excel 单元格32,767字符限制，不截断长名。同一年度不能重复同一版型。每份业务上传文件不超过10 MB，最多2,000条版型年度记录及1,000项新增明细；原完整 BC 保持原结构要求。

MSRP明确为数值0的损益列会排除；空白、非法值和没有保存数值的公式不等于0。销量为0而售价有效的列可以保留。完全未填写的列不导入。

损益处理顺序：识别列与科目 → 校验输入 → 读取直接录入值 → 对空白/受支持公式的合计按现有明细重算 → 保留实际合计差额 → 建立基线。直接填入的有限数值优先，包括0；不因为与标准公式不同而强行覆盖。常见舍入差异按容差处理。新增明细须有可识别上级，填独立数值，不执行任意新增公式。

当前 BOM 层级为：BOM成本总额 → 基准“- BOM成本”、内含赠送配置、供应商模具分摊。三个子项只汇总一次，再进入成本总额。旧 BC 中 BOM 外单列赠送配置保留独立层级，不因名称相似擅自去重。新增独立明细保留自身金额，普通比例调整不隐含改变它；固定费用下的独立明细保留基线预算。

## 4. 科目与数据：核对依据并编辑

“科目归因”和原“编辑数据”窗口合并为“科目与数据”。采用紧凑行展示科目、输入方式、参数及单车结果；计算依据可统一展开，原值仅在有变化时显示，保存区停留在页面底部。先选版型，再选年度；可搜索科目或公式，切换版型、年度或分析页面保留未保存草稿。页面编辑整份当前基础表，不受分析页面的查看筛选和展示情景影响。演示数据只读；对标数据继续独立。

输入框默认精简小数显示：金额最多2位、费率最多4位、万元预算最多6位，不补多余的0；非零小值保留可辨识数值。悬停可查看完整数值，手动输入时不截断。显示取舍、点入及离开输入框均不修改底层数据，实际保存按输入的完整数值计算。

| 科目 | 可使用的输入 | 计算关系 |
|---|---|---|
| 销量 | 台数 | 非负整数，作为分摊和加权的前置参数 |
| 售价 | 单车金额 | 元/台，作为测算的基础价格输入 |
| BOM、收入抵减、其他成本费用及上传新增明细 | 单车金额或费率 | 单车沿用底表符号；费率可选择净收入、含税售价或BOM成本绝对值作为分母 |
| VAT、消费税、附加税、质保 | 费率或单车金额 | 默认推荐原科目公式，也可改选可用分母；费率填百分数，例如13表示13% |
| 关税 | 税基×税率、单车金额或自选分母费率 | 关税单车金额＝−计税基数×税率；只有明确选择税基×税率时才启用 |
| 固定制造、研发、固定销交服 | 总额分摊、单车金额或费率 | 总额填该版型该年度的费用预算，按该记录销量换算单车分摊；零销量保留总额 |
| 变动销交服 | 费率或单车金额 | 默认推荐净收入，允许改选分母；原上传金额不会自动切换为费率 |
| 集团分摊 | 费率、总额分摊或单车金额 | 采用所选方式一次计入费用及EBIT |
| MIX、净收入、成本/费用合计、毛利、EBIT | 修改其构成 | 自动计算，点击构成科目可定位输入，不手工覆盖汇总结果 |

费用总额以万元输入，正数表示支出，负数表示冲回；单车金额采用底表符号，通常成本、费用、税费和抵减为负数。单条编辑中的分摊只针对所选版型年度，不把一个项目总预算重复套用到每条记录，也不在筛选后重新分配。纯总额模式下修改销量只改变单车分摊；单车模式下总费用随销量变化。若预算下有按费率录入的明细，仅固定余额保留预算，费率部分随分母和销量联动，零销量保留固定余额。若要重新设为固定总预算，须先把费率明细改为单车金额，避免两种要求冲突。

系统推荐分母，用户可以改选：一般成本费用推荐净收入，收入抵减等会避免使用依赖自身的净收入；已有税费可继续用原公式。选择自选分母时，科目金额＝−所选分母×费率，BOM分母采用绝对值；正费率表示扣减，负费率表示冲回。系统排除循环引用和未填写分母；分母为真实0时计算结果为0。切换方式或分母会尽量按当前金额换算费率，无有效分母或金额缺失时需自行填写，不能猜测。

未修改的记录保留上传来源的规则和原值；能准确还原上传值时，页面直接呈现对应费率或总额，存在录入差额的税费仍显示原金额。明确改为费率后按新费率和相应基数重算；明确改为单车金额后该金额不再跟随售价自动计算。此类选择是业务口径修改，会影响后续情景。

明细变动按增量传到上级，保留原有合计差额。已有总额预算也承接随后修改的明细；同一批修改中明确重新填写的总额优先。选择“按明细汇总”会用明细之和替代该合计。缺失明细仍是未知，填0是实际0。特殊调整中的显式费用替换总额优先于基础表输入方式。

### 批量调整

在“科目与数据”顶部展开“批量调整”。版型和年度分别多选，两者交集决定修改范围；默认当前版型年度，选择“全部”才扩展范围。每批可添加多个科目，按“改为、增减、按百分比调整”统一处理；粘贴四列调整清单也进入同一预览，不采用Excel导出后回传覆盖方案。

批量区统一按业务支出正数填写成本、费用、税费和收入抵减，冲回填负数；单条编辑仍采用损益表符号。例：BOM改为110000表示成本11万元/台，增减10000表示每台增加1万元成本；费率改为2表示2%，增减1表示增加1个百分点，按百分比调整10表示原费率乘1.1。“改为”明确切换输入方式；费率旁可改选分母，粘贴清单后也应核对分母。增减或百分比调整仅用于当前相同输入方式及相同分母，改分母应选“改为”并填写新费率，缺失值不能猜测。

固定制造、研发、固定销交服及集团分摊可以输入“范围总预算”：所选全部版型年度共用一笔预算，按本批修改后的销量或按记录平均分配，保存后各记录的预算固定；不含费率明细时，后续销量只改变单车分摊。全范围销量为0时不能按销量分配，可选平均分配。同批合计及其明细、重复科目，以及同编号却含义不同的自定义科目会提示冲突，须缩小范围或分批处理。上级按费率计费时须先修改上级，不能靠改明细覆盖费率结果。

默认保护已有人工修改，包含关联的可编辑合计及明细；需要替换时明确勾选允许覆盖。总预算范围包含受保护记录时停止整批，避免把预算全部转分给其余记录。保护依据当前记录与原始上传的金额及取数方式差异判断，Mapping生成记录以最初生成值为对照，原规则快照另行保留。

先核对修改前后输入及当前基础表毛利、EBIT变化，再“保存这批修改”。存在单条编辑草稿时同时保存，预览影响以这些草稿为起点；保存后重置当前情景参数和Mix，原始上传及已存情景不变。网页当前编辑会话可撤销上一批，保留该批之前的单条编辑；后续另存基础修改或有新草稿时不允许跨修改撤销，重新打开项目后也不保留此撤销入口的历史。下载项目保留生效后的数据及取数方式。上传损益及Mapping生成的基础数据均支持批量调整。

保存前预览整份基础表的销量、净收入、EBIT及固定预算变化。保存才更新分析结果，并重置当前参数和Mix；已存情景保留自己的底表与输入方式。保存时保留最初接入数据及版本，可通过“恢复上传原始值”或“恢复生成原始值”预览后保存。放弃修改不影响已保存数据。

有未保存科目草稿时，下载/打开项目或再次接入数据会引导回本页，需先保存或放弃草稿；切页本身不会丢失草稿。保存后再“下载项目”才能长期保留输入方式、费率和预算。刷新/关闭页面前仍需下载项目。

## 5. 参数、销量与 Mix 的作用范围

| 入口 | 作用范围 | 单位与方向 |
|---|---|---|
| 编辑数据 | 整份当前基础表，逐条选择版型年度 | 台、带符号元/台 |
| 价格与成本参数 | 面板内“调整版型／调整年度”；默认全表，独立于顶部查看筛选 | 变化率%；售价、BOM与抵减目标金额填正数元/台 |
| 特殊费用 | 顶部查看筛选中的记录 | 费用总额正数万元；所得税率作用于整套情景 |
| 销量与Mix | 独立项目/国家/阀点及分配年度 | 整数台数、占比%；锁定的是占比 |

仅选范围不会写入假设。所有百分比相对对应基线；局部设置覆盖全局设置；局部百分比已设置时不会意外继承全局绝对目标。明确0不能被当作空值。多版型/多年度的不同金额按当前销量加权显示，查看加权值不将其回写给每条记录。

售价、BOM与抵减可改比例或目标单车金额，两者联动。售价变化按各科目的当前输入方式带动 VAT、消费税、附加税与质保；明确按单车金额设置的科目保留单车金额。明确设置为售价费率的抵减随售价变化，单车抵减保持单车金额。关税的基数和费率在“科目与数据”中设置；未明确启用时保留上传金额。售价0可以用于情景测算，但无法作为完整损益上传模板的有效售价；损益导出前会提示。

固定制造、研发、固定销交服默认按预算总额处理；在“科目与数据”明确选为单车金额时按单车金额与销量计算。默认预算未显式填写时由基线单车值乘基线销量得到；销量变化改变单车分摊，不改变预算。特殊费用总额按当前所选范围的底表构成分配并捕获到记录，后续查看筛选、销量和Mix不重新分配；输入0替换为0，恢复只作用于所选范围。

销量总台数、变化比例、版型台数和Mix控制同一有效计划。按所选范围先分配，再应用查看筛选；筛选剩一款不会让它独占全部销量。计划中总量与版型年度台数保持整数且精确守恒。锁定版型占比后其占比保持不变；其他版型平衡剩余份额。年度分布采用首次建立计划时捕获的权重，零量按既定底表/均分回退。重叠记录范围不能同时建立冲突计划，需回到已有计划编辑。

## 6. 计算链路与取值解释

以下公式采用带符号科目：成本、费用、税费及收入抵减通常为负数。

| 科目 | 基础关系 |
|---|---|
| VAT | −含税MSRP ÷（1＋增值税率）×增值税率 |
| 净收入 | MSRP＋VAT＋收入抵减 |
| 消费税 | −净收入×消费税率 |
| 城建及教育附加 | [min(0, VAT−BOM成本×增值税率)＋消费税]×附加税率 |
| 质保金 | −MSRP×质保计提比例 |
| 成本总额 | BOM、BOM外独立赠送、税金、制造、物流、质保、其他成本等带符号科目合计 |
| 毛利 | 净收入＋成本总额 |
| 费用总额 | 研发＋销交服＋市场＋集团分摊及已有差额 |
| EBIT | 毛利＋费用总额 |

这是模板的建模口径，并非外部税务政策判断。税率及来源计算差异使用实际底表，不因文档中的示例税率而改写用户数据。未明确修改输入方式时，损益格式直接录入的税费/合计优先，调参在这些基线金额上叠加变化，保留原差额。例如税费原值−200元/台、相关税基增加1,000元/台、税率3%，调整后为−230元/台。

“科目与数据”把取数方式、分母、参数及结果放在紧凑的同一行，支持分类展开和搜索；点击“显示计算依据”可查看公式与来源说明。底表税费不同于公式时，提示“以录入值为基准”；父级不同于子项合计时，提示“包含合计差额”；部分明细缺失时明确提示未知。公式不会反向覆盖当前金额。损益悬浮与瀑布使用同一取值解释；差额单独列示，保持金额可衔接。

先逐条计算总额，再汇总。单车值＝对应总金额÷对应总销量；毛利率/EBIT率＝对应利润总额÷净收入。不能简单平均单车金额或利润率。销量为0时单车值显示“—”，固定亏损仍保留在总额；净收入为0时利润率显示“—”。未知明细显示“—”，真实0显示0，混合已知与未知的标准明细汇总保持未知。

所得税按同一项目、国家、年度的所选版型合计EBIT计税：max(合计EBIT,0)×所得税率，默认15%。不同项目、国家、年度分别计算后加总；不确认亏损税收收益，不跨年抵亏。筛选单一版型改变税基范围，因此分别筛选的税后利润不一定可直接相加。

## 7. 情景保存、查看与比较

情景名称可空，自动生成不重名名称；用稳定标识区分。加入情景比较保存当时假设、费用分配、Mix与锁定状态、查看范围及底表快照。保存后继续调参不会改写旧情景。选择情景只是查看，不恢复或应用其参数，也不改变筛选。

项目总览、情景比较、损益明细统一按顶部当前查看范围重算选定情景，使用它保存时的底表及假设。保存时范围作为记录保留，不再导致比较页冻结在另一套范围。对标页使用其独立比较范围。相同假设且底表版本相同才合并“当前调整”与已存情景；基线不同不合并。

保存数量不再限制为四个，新增不会删除旧方案。图表最多同时选4个已存方案，默认显示最近4个；切换参与对象只改变图表选择，不删除数据。表格保留全部方案，标签右上角删除只作用于对应ID，相关选择器回退到当前/基线。基线、当前不能删除。项目文件保留全部已存方案；未下载的删除仍只影响本次会话。

基础数据修订后，旧方案标记“历史底表版本”。此时与新基线的差额可能同时包含底表修订及参数变化。比较图与毛利/EBIT变动瀑布均使用同一账本，不把差额包装成纯参数效应。

## 8. 页面与图表

页面为：项目总览、情景比较、对标比较、现金流快照、损益明细、科目与数据。顶部导航、查看筛选及展开的项目参数一起固定；参数可收起，输入保留。对标和现金流导航较淡，但可正常访问。

总览前以三行浅色高亮文字呈现当前测算假设：期间与情景、计划销量及加权售价/BOM、研发分摊及销交服/固定制造费用。没有大数字卡片，也不展示投资总额。金额来自当前展示情景及查看范围，历史情景使用原底表；小金额改用万元或元，避免非零预算显示成0.00亿元。演示数据明确标注。

总览顺序：三行测算假设 → 销量/净收入/毛利率/EBIT率四卡 → 九项版型贡献 → 生命周期经营表现 → 九项版型指标选择、横向柱图及年度数值表 → MSRP至EBIT连续瀑布。没有独立版型分析/盈亏平衡页，也没有底部版型年度折线。单年时隐藏无比较意义的年度图。

版型贡献的销量占比分母忽略“查看版型”筛选，仍保留相同项目、国家、阀点、年度与有效情景；单选不会自动变成100%。生命周期单车利润柱与利润率线按同一年度总额、销量及净收入计算。名称完整换行，实际业务名称不改写。

连续瀑布默认单车元/台，可切总额亿元。净收入之后的科目标注带符号的占净收入比，净收入为0显示“—”。MSRP、VAT、抵减及净收入本身不标比率。合计柱悬浮只显示自身金额，其余科目显示构成及公式。金额精度、正负号和细小项目真实比例保留。

情景图进入、口径/范围切换时柱线点约0.75秒同步入场；新增只播放新系列，保留系列和瀑布保持显示。连续调参直接更新金额，删除不重播其他系列；主动切换瀑布端点才重播。悬浮明细直接显示，遵循减少动态效果设置。窄屏图表适配或分页，损益宽表保留横向查看。

## 9. 对标与现金流

对标数据独立命名、计算和选择范围，不继承基础表参数。基础表可以选当前/基线/已存情景；基线名称为“当前底表基线”。年度和版型使用共同分类，展示单车金额及利润率，各数据集为独立系列，不相加。没有对应年度或版型则留空，不补0或退回全部。范围不同时明确提示。

现金流是完整项目的独立上传快照，不随经营筛选、底表经营编辑或情景变化推导。原工作簿两种现金流算法分别显示，尚未由业务确认哪一种作为投资结论。没有现金流时显示空态。

四张现金流卡为NPV、期末累计现金流、最大累计资金缺口、静态回收期。首期t=0，NPV按所选折现率折现，默认9%。资金缺口为累计最低点的绝对值，最低点非负时为0。回收期在首次出现缺口后累计回正的年度插值计算，包含建设期、未折现；未回正显示“未回收”，从未出现缺口显示“—”，首次回正后再现缺口另作提示。切换现金流口径更新全部卡片；折现率只影响NPV及折现值。

研发分摊不等于研发付款，折旧不等于当期资本开支；付款节奏、营运资金等未确认前，不用EBIT替代现金流。原表的BOM重复标签、现金流可能重复引用及特定月份回收公式仍需业务核查，未在本次实用性修复中擅自改变。历史原表核对与数值证据保留于归档。

## 10. 两种 Excel 导出及项目恢复

| 操作 | 保留什么 | 范围 |
|---|---|---|
| 导出当前筛选损益表 | 带格式的核查报表，当前单车/总额、分组、展示/对照/差额及假设 | 当前查看范围 |
| 导出完整损益表 | 按上传模板样式写所选情景的绝对值、实际新增科目和缺失状态 | 该情景所用底表的全部版型年度，不受查看筛选影响；不导出差额 |
| 下载项目 / 打开项目 | 来源口径、上传原始值、当前修订、参数/Mix、全部情景、独立对标及现金流 | 整个当前工作状态 |

完整导出保持明细空值与真实0的区别；合计按对应计算结果写数值，避免 Excel 重算消除用户录入差额。零销量有固定预算时无法换算成单位模板，零售价、非整数台数、正向标准成本等也会提示具体原因；可改用筛选报表总额保存结果。导出入口提前提示已识别的限制，不更改金额、补造售价或销量。

完整 Excel 是损益结果快照，不是项目备份。重新上传会按损益格式建立固定集团预算，并以文件名等重建身份；不能完整恢复原来源类型、项目/国家/阀点、现金流、科目输入方式及分摊预算、当前假设、Mix锁定及所有情景。继续工作请用项目文件。两种文件用途不同，不应把“基准总额相同”误认为“后续调参规则完全相同”。


## 本地桌面版：项目、版本与操作记录

Mac和Windows桌面版提供独立的本地项目库；网页版仍通过“下载项目 / 打开项目”保存恢复。桌面版不会自动同步两台电脑，也不会把项目数据上传到网站。

首次打开选择“新建并接入表格”，进入数据接入窗口后上传Excel或CSV；已有Checkmi项目备份（.json）选择“导入 Checkmi 备份”。误选表格不会创建或覆盖项目，界面会提示正确入口。输入停止约半秒后自动保存到本机，保存成功才显示“已保存到本机”；尚未应用的科目草稿单独保留，不参与经营结果。关闭应用会先等待当前保存完成；写入失败会保留窗口并显示错误，可重试、另存当前工作或保留为新项目。

“版本与记录”可以按业务阶段命名版本并填写修改说明，例如初版、评审版或销量调整版。版本保存完整底表、原始上传、科目取数方式、假设、Mix、已存情景和草稿；后续修改不覆盖旧版。查看差异时按各自全部版型年度的当前参数展示销量、净收入、毛利和EBIT，并列出科目及参数的修改前后值。历史草稿不参与结果计算。连续输入合并记录，不逐键记录；查看范围变化也会保留。

“从此版本继续”会先保存恢复前的工作，再生成恢复版本和记录，原有历史保留。项目版本用于保存阶段成果；测算情景仍用于同一工作中的不同业务假设比较，两者独立。

“导出项目包”携带当前状态、版本和操作记录；在另一台电脑导入会建立独立副本，不覆盖本机已有项目。Mac与Windows使用同一种项目包，后续修改各自保存。项目包限200 MB；单个完整项目状态仍限50 MB。兼容旧.checkmi.json项目文件；“导出网页版当前状态”只包含当前已生效状态与测算情景，不携带桌面历史，需先应用或放弃科目草稿。

本地保存不能替代备份；重要阶段可把项目包保存到另一块磁盘。数据位置在项目库底部显示，程序升级沿用原位置；安装包不包含用户数据。Excel继续作为表格输入和结果导出，完整历史通过项目包迁移。
