# Checkmi · 业务逻辑说明

版本：1.82　日期：2026年9月29日

本文是当前规则。旧版累计说明已归档，不再用“后面的修订覆盖前面的修订”解释互相冲突的段落。看板在浏览器本地计算；默认演示数据用于熟悉操作，不能视为实际经营数据。

## 1. 工作顺序与保存

1. 通过“接入数据”上传基础表，核查预览后应用。
2. 原表填错或需要补录时，用“编辑数据”修改基础表；经营假设用“项目参数”调整。
3. 选择查看范围，核对总览和损益。需要留存假设时“加入情景比较”。
4. 用“下载项目”保存 `.checkmi.json` 文件。下次用“打开项目”继续测算。
5. 对外核查损益结果时，再导出 Excel 报表或完整损益模板。

“保存修改”和“加入情景比较”先写入本次页面会话。刷新、关闭页面仍会清空未下载的工作；有未下载内容时，浏览器在允许的情况下提供离开提示。项目文件保留基础数据来源规则、上传原始值、当前修订、现金流、独立对标、当前参数、Mix、全部已存情景及顶部查看范围。后续有修改，应重新下载文件。浏览器不会自动覆盖旧下载文件，也没有向服务器上传用户数据。

“打开项目”会替换当前工作，需要保留当前工作时先下载。文件完整校验通过后才替换；文件错误时保留当前工作。项目文件上限50 MB。图表分页、展开状态等临时界面设置以及现金流页手动选择的折现率/口径不属于项目文件；打开后可重新选择。项目文件与业务上传 JSON 是两种不同格式，分别从“打开项目”和“接入数据”读取。

## 2. 数据来源与范围

一条经营记录对应“项目 × 国家 × 阀点 × 版型 × 年度”。同名版型如果项目、国家或阀点不同，不能混为一条。汇总列、Average、生命周期合计不能再次作为明细加入。金额、比例和销量采用原始精度计算，显示取舍不改变底层数值。

| 来源 | 输入含义 | 集团分摊的默认规则 | 现金流 |
|---|---|---|---|
| 原完整 BC 工作簿 | 原结构的带符号单车值及来源位置 | 按该版型年度基线“集团分摊÷净收入”随净收入与销量联动 | 读取独立现金流表 |
| 标准底表（Excel/CSV/业务 JSON） | 正数单车成本/抵减与比例，系统转为带符号科目 | 按输入的集团分摊率随净收入与销量联动 | 标准模板不含现金流 |
| 损益格式 Excel | 带符号单车明细；允许直接录入税费与合计 | 上传单车分摊×上传销量形成固定预算，后续销量/Mix不改该预算 | 不拼入演示现金流 |

集团分摊始终进入费用及 EBIT 一次。特殊调整显式填写集团分摊总额后，所选记录使用填写的固定金额；恢复底表后回到各自来源规则。原完整 BC 的集团分摊原本不在费用合计内，看板补计这笔扣减；损益格式已包含，不能再重复扣减。

普通上传入口首次默认替换基础，后续默认追加对标；对标页入口默认追加。明确替换基础会重置当前参数、Mix与旧基础的情景；独立对标继续保留。多文件先解析核查再统一应用，失败文件不会造成部分替换。页面内基础编辑则保留已存情景，详见第4节。

## 3. 模板、识别与空值

标准模板在“数据填写”页逐行填入真实数据；“填写示例”页仅供参考。必填字段涵盖身份、年度、销量、售价、各成本费用合计与费率。金额按正数元/台，销量按台，费率用小数或 Excel 百分比，例如0.13或13%。无发生额明确填0。标准表的 BOM 不包含另列赠送配置。兼容旧“车型”及新“版型”表头，同义字段重复时提示错误。

损益模板在真实年度/版型的“单车（元）”列填写：Sales为非负整数台数，MSRP为正数元/台，成本、费用和收入抵减使用负号。收入比、Average、生命周期汇总和分隔列不参与上传取数。成本明细空白保留为“未填写”；确实为零应填0。明细缺失不会阻止使用已有父级合计，也不会补造拆分。

模板保留原 BC 字体、灰色斜体、颜色、边框、缩进、列宽、行高、数值格式和底部参数/填写说明，冻结C6，缩放70%。显示位数不影响数值精度。旧版简表继续兼容。

损益格式按标题含义识别年度、版型和单位，支持增删年度/版型、SOP至SOP+999或2000至2099日历年；同一份数据不能混用两种年度体系。支持带年份的现状表头。名称按实际值保留；完整导出仅受 Excel 单元格32,767字符限制，不截断长名。同一年度不能重复同一版型。每份业务上传文件不超过10 MB，最多2,000条版型年度记录及1,000项新增明细；原完整 BC 保持原结构要求。

MSRP明确为数值0的损益列会排除；空白、非法值和没有保存数值的公式不等于0。销量为0而售价有效的列可以保留。完全未填写的列不导入。

损益处理顺序：识别列与科目 → 校验输入 → 读取直接录入值 → 对空白/受支持公式的合计按现有明细重算 → 保留实际合计差额 → 建立基线。直接填入的有限数值优先，包括0；不因为与标准公式不同而强行覆盖。常见舍入差异按容差处理。新增明细须有可识别上级，填独立数值，不执行任意新增公式。

当前 BOM 层级为：BOM成本总额 → 基准“- BOM成本”、内含赠送配置、供应商模具分摊。三个子项只汇总一次，再进入成本总额。旧 BC 中 BOM 外单列赠送配置保留独立层级，不因名称相似擅自去重。新增独立明细保留自身金额，普通比例调整不隐含改变它；固定费用下的独立明细保留基线预算。

## 4. 编辑基础数据与恢复

“编辑数据”只处理已上传基础表。左侧按项目/国家/阀点/版型分组，每个版型显示一次；右侧选择年度。切换版型优先保留当前年度，没有该年度时取最早年度。查找、切换和展开不会丢失各记录草稿；圆点标识尚未保存修改。

“本次修改前”指打开编辑器时的当前基础值，不冒充最初上传值。金额按元/台、销量按台。成本、费用和抵减通常为负；真实冲回可以保留正数，但正数成本不能写入要求负号的完整损益模板。

明细改动以增量逐级更新上级，保留原合计差额；直接填写合计优先，明确0仍有效；主动清空合计才按已列明细汇总。普通明细清空保持未知。MIX、净收入、成本总额、费用总额、毛利及EBIT按既有依赖计算。用户直接修改税费金额时以该金额为准。

底部预览针对整份基础表，不受顶部查看筛选影响。改底表销量会用新销量重建“单车费用×销量”的固定预算；预览列出固定制造、研发、固定销交服预算的前后变化。例如100台×4,000元/台改为0台，新基线预算是0；用项目参数将销量降到0，旧40万元固定预算仍保留。这两种入口分别表达基础修订和情景模拟。

点击“保存修改”才统一生效。非法数值、零售价和新填写的小数销量会阻止保存。保存保持来源类型、名称、记录身份、科目、费率、原来源地址和现金流，建立下一次修订，并重置当前参数及Mix。已存情景保留各自的底表快照，后续修订不会改写它们。取消或关闭放弃草稿。

首次修订时另存上传原始值。“恢复上传原始值”先载入预览，检查后点击保存才恢复；也可撤销恢复。恢复产生新修订，仍保留已存情景。修订次数用于区分当前基线，不是可逐步撤销的完整编辑历史。来源地址只说明上传定位，网页修订不会写回原文件；损益下钻分别列出展示、对照情景所用底表值。

## 5. 参数、销量与 Mix 的作用范围

| 入口 | 作用范围 | 单位与方向 |
|---|---|---|
| 编辑数据 | 整份上传基础表，逐条选择版型年度 | 台、带符号元/台 |
| 价格与成本参数 | 面板内“调整版型／调整年度”；默认全表，独立于顶部查看筛选 | 变化率%；售价、BOM与抵减目标金额填正数元/台 |
| 特殊费用 | 顶部查看筛选中的记录 | 费用总额正数万元；所得税率作用于整套情景 |
| 销量与Mix | 独立项目/国家/阀点及分配年度 | 整数台数、占比%；锁定的是占比 |

仅选范围不会写入假设。所有百分比相对对应基线；局部设置覆盖全局设置；局部百分比已设置时不会意外继承全局绝对目标。明确0不能被当作空值。多版型/多年度的不同金额按当前销量加权显示，查看加权值不将其回写给每条记录。

售价、BOM与抵减可改比例或目标单车金额，两者联动。售价变化带动 VAT、消费税、附加税与质保；抵减不自动随售价变化。关税税率控制仍为预留，原输入关税保留，不产生隐含调参效果。售价0可以用于情景测算，但无法作为完整损益上传模板的有效售价；损益导出前会提示。

固定制造、研发、固定销交服按预算总额处理，未显式填写时由基线单车值乘基线销量得到；销量变化改变单车分摊，不改变预算。特殊费用总额按当前所选范围的底表构成分配并捕获到记录，后续查看筛选、销量和Mix不重新分配；输入0替换为0，恢复只作用于所选范围。

销量总台数、变化比例、版型台数和Mix控制同一有效计划。按所选范围先分配，再应用查看筛选；筛选剩一款不会让它独占全部销量。计划中总量与版型年度台数保持整数且精确守恒。锁定版型占比后其占比保持不变；其他版型平衡剩余份额。年度分布采用首次建立计划时捕获的权重，零量按既定底表/均分回退。重叠记录范围不能同时建立冲突计划，需回到已有计划编辑。

## 6. 计算链路与取值解释

以下公式采用带符号科目：成本、费用、税费及收入抵减通常为负数。

| 科目 | 基础关系 |
|---|---|
| VAT | −含税MSRP ÷（1＋增值税率）×增值税率 |
| 净收入 | MSRP＋VAT＋收入抵减 |
| 消费税 | −净收入×消费税率 |
| 城建及教育附加 | [min(0, VAT−BOM成本×增值税率)＋消费税]×附加税率 |
| 质保金 | −MSRP×质保计提比例 |
| 成本总额 | BOM、BOM外独立赠送、税金、制造、物流、质保、其他成本等带符号科目合计 |
| 毛利 | 净收入＋成本总额 |
| 费用总额 | 研发＋销交服＋市场＋集团分摊及已有差额 |
| EBIT | 毛利＋费用总额 |

这是模板的建模口径，并非外部税务政策判断。税率及来源计算差异使用实际底表，不因文档中的示例税率而改写用户数据。损益格式直接录入的税费/合计优先，调参在这些基线金额上叠加变化，保留原差额。例如税费原值−200元/台、相关税基增加1,000元/台、税率3%，调整后为−230元/台。

“科目归因”显示基础公式或“数据直接接入”，支持分类和搜索。底表税费不同于公式时，提示“以录入值为基准”；父级不同于子项合计时，提示“包含合计差额”；部分明细缺失时明确提示未知。公式不会反向覆盖当前金额。损益悬浮与瀑布使用同一取值解释；差额单独列示，保持金额可衔接。

先逐条计算总额，再汇总。单车值＝对应总金额÷对应总销量；毛利率/EBIT率＝对应利润总额÷净收入。不能简单平均单车金额或利润率。销量为0时单车值显示“—”，固定亏损仍保留在总额；净收入为0时利润率显示“—”。未知明细显示“—”，真实0显示0，混合已知与未知的标准明细汇总保持未知。

所得税按同一项目、国家、年度的所选版型合计EBIT计税：max(合计EBIT,0)×所得税率，默认15%。不同项目、国家、年度分别计算后加总；不确认亏损税收收益，不跨年抵亏。筛选单一版型改变税基范围，因此分别筛选的税后利润不一定可直接相加。

## 7. 情景保存、查看与比较

情景名称可空，自动生成不重名名称；用稳定标识区分。加入情景比较保存当时假设、费用分配、Mix与锁定状态、查看范围及底表快照。保存后继续调参不会改写旧情景。选择情景只是查看，不恢复或应用其参数，也不改变筛选。

项目总览、情景比较、损益明细统一按顶部当前查看范围重算选定情景，使用它保存时的底表及假设。保存时范围作为记录保留，不再导致比较页冻结在另一套范围。对标页使用其独立比较范围。相同假设且底表版本相同才合并“当前调整”与已存情景；基线不同不合并。

保存数量不再限制为四个，新增不会删除旧方案。图表最多同时选4个已存方案，默认显示最近4个；切换参与对象只改变图表选择，不删除数据。表格保留全部方案，标签右上角删除只作用于对应ID，相关选择器回退到当前/基线。基线、当前不能删除。项目文件保留全部已存方案；未下载的删除仍只影响本次会话。

基础数据修订后，旧方案标记“历史底表版本”。此时与新基线的差额可能同时包含底表修订及参数变化。比较图与毛利/EBIT变动瀑布均使用同一账本，不把差额包装成纯参数效应。

## 8. 页面与图表

页面为：项目总览、情景比较、对标比较、现金流快照、损益明细、科目归因。顶部导航、查看筛选及展开的项目参数一起固定；参数可收起，输入保留。对标和现金流导航较淡，但可正常访问。

“项目关键假设”先呈现领导汇报所需的业务前提：测算期间、版型与年度数、计划销量、含税均价、单车BOM、研发分摊、销交服费用（含固定部分）及固定制造费用。全部数值取自当前展示情景和查看范围；历史情景使用其原底表。含税均价与BOM按销量加权；费用以支出正数列示，冲回为负数。零销量时单车数值为“—”，固定预算仍保留。默认演示数据有明确标记。

投资总额目前没有独立接入字段，因此标为“待补充”，不使用研发摊销、负现金流或最大资金缺口推定。研发分摊是计入损益的费用，不等于研发现金投入。摘要不改变损益、现金流或Excel的计算口径。

总览顺序：项目关键假设高亮块 → 销量/净收入/毛利率/EBIT率四卡 → 九项版型贡献 → 生命周期经营表现 → 九项版型指标选择、横向柱图及年度数值表 → MSRP至EBIT连续瀑布。没有独立版型分析/盈亏平衡页，也没有底部版型年度折线。单年时隐藏无比较意义的年度图。

版型贡献的销量占比分母忽略“查看版型”筛选，仍保留相同项目、国家、阀点、年度与有效情景；单选不会自动变成100%。生命周期单车利润柱与利润率线按同一年度总额、销量及净收入计算。名称完整换行，实际业务名称不改写。

连续瀑布默认单车元/台，可切总额亿元。净收入之后的科目标注带符号的占净收入比，净收入为0显示“—”。MSRP、VAT、抵减及净收入本身不标比率。合计柱悬浮只显示自身金额，其余科目显示构成及公式。金额精度、正负号和细小项目真实比例保留。

情景图进入、口径/范围切换时柱线点约0.75秒同步入场；新增只播放新系列，保留系列和瀑布保持显示。连续调参直接更新金额，删除不重播其他系列；主动切换瀑布端点才重播。悬浮明细直接显示，遵循减少动态效果设置。窄屏图表适配或分页，损益宽表保留横向查看。

## 9. 对标与现金流

对标数据独立命名、计算和选择范围，不继承基础表参数。基础表可以选当前/基线/已存情景；基线名称为“当前底表基线”。年度和版型使用共同分类，展示单车金额及利润率，各数据集为独立系列，不相加。没有对应年度或版型则留空，不补0或退回全部。范围不同时明确提示。

现金流是完整项目的独立上传快照，不随经营筛选、底表经营编辑或情景变化推导。原工作簿两种现金流算法分别显示，尚未由业务确认哪一种作为投资结论。没有现金流时显示空态。

四张现金流卡为NPV、期末累计现金流、最大累计资金缺口、静态回收期。首期t=0，NPV按所选折现率折现，默认9%。资金缺口为累计最低点的绝对值，最低点非负时为0。回收期在首次出现缺口后累计回正的年度插值计算，包含建设期、未折现；未回正显示“未回收”，从未出现缺口显示“—”，首次回正后再现缺口另作提示。切换现金流口径更新全部卡片；折现率只影响NPV及折现值。

研发分摊不等于研发付款，折旧不等于当期资本开支；付款节奏、营运资金等未确认前，不用EBIT替代现金流。原表的BOM重复标签、现金流可能重复引用及特定月份回收公式仍需业务核查，未在本次实用性修复中擅自改变。历史原表核对与数值证据保留于归档。

## 10. 两种 Excel 导出及项目恢复

| 操作 | 保留什么 | 范围 |
|---|---|---|
| 导出当前筛选损益表 | 带格式的核查报表，当前单车/总额、分组、展示/对照/差额及假设 | 当前查看范围 |
| 导出完整损益表 | 按上传模板样式写所选情景的绝对值、实际新增科目和缺失状态 | 该情景所用底表的全部版型年度，不受查看筛选影响；不导出差额 |
| 下载项目 / 打开项目 | 来源口径、上传原始值、当前修订、参数/Mix、全部情景、独立对标及现金流 | 整个当前工作状态 |

完整导出保持明细空值与真实0的区别；合计按对应计算结果写数值，避免 Excel 重算消除用户录入差额。零销量有固定预算时无法换算成单位模板，零售价、非整数台数、正向标准成本等也会提示具体原因；可改用筛选报表总额保存结果。导出入口提前提示已识别的限制，不更改金额、补造售价或销量。

完整 Excel 是损益结果快照，不是项目备份。重新上传会按损益格式建立固定集团预算，并以文件名等重建身份；不能完整恢复原来源类型、项目/国家/阀点、现金流、当前假设、Mix锁定及所有情景。继续工作请用项目文件。两种文件用途不同，不应把“基准总额相同”误认为“后续调参规则完全相同”。
